# 中文写作规则

改编自 ASD-STE100（简化技术英语，航空维修手册用的受控语言）和 [danyuchn/asd-ste100-skill](https://github.com/danyuchn/asd-ste100-skill)（MIT 许可）。原规则只管英文，这里换成中文的写法，并补上中文特有的毛病。

目标是**消除歧义**，不是把字删到最少。句子已经没有歧义了，就停手。

## 句子

| 规则 | 这样写 | 不这样写 |
|---|---|---|
| 结论先行 | 第一句就回答读者问题 | 先铺背景，结论放最后 |
| 句子长度 | 步骤 ≤20 字，说明 ≤30 字（不算标点和英文） | 一句话三四个逗号连下去 |
| 一句一事 | 「打开文件。读第 3 行。」 | 「打开文件并读第 3 行，然后检查是否匹配。」 |
| 说清谁做什么 | 「脚本删除了缓存。」 | 「缓存被删除了。」（不知道谁删的） |
| 不用分号 | 拆成两句 | 「A 已完成；B 还在跑」 |
| 3 步以上用列表 | 1. 2. 3. | 把一串步骤塞进一个长句 |
| 一段一个话题 | 每段 ≤5 句 | 一段里讲三件事 |

## 用词

| 规则 | 这样写 | 不这样写 |
|---|---|---|
| **一个东西只叫一个名字** | 选定「智能体」，全文都叫「智能体」 | 一会儿「智能体」，一会儿「代理」，一会儿「执行器」 |
| 动词别变名词 | 「分析日志」「帮你」 | 「对日志进行分析」「为你提供帮助」「做出……的决定」 |
| 定语不超过两层 | 「主仓库的同步脚本」 | 「公开版主仓库自动化每日同步脚本」 |
| 术语首次出现给一句解释 | 「爻（卦里的一条横线）」 | 术语直接上，从不解释 |
| 中英混用先给中文 | 「置信度（confidence）」 | 「这个 confidence 比较 low」 |
| 删掉自夸的形容词 | 删掉，或换成能证明它的数字 | 「强大的」「无缝」「极致」「一站式」「颠覆性」 |
| 口号词换成具体做了什么 | 「每天自动核对一次库存」 | 「降本增效、提质赋能」「抓手」「闭环」「打通」 |
| 删掉叠起来的模糊词 | 说清楚，或删掉。原文真没把握，留一个「可能」就够（见下面「保住把握程度」） | 「值得注意的是，这在一定程度上可能有助于」 |

## 不能改的东西

| 规则 | 说明 |
|---|---|
| 保住把握程度 | 「可能失败了」不能改成「失败了」。「也许是 X 导致的」不能改成「X 导致的」。原文的把握程度就是内容 |
| 不加原文没有的事实 | 改写后读着更顺，是因为你补了原因、频率或机制？那就不是改写了，删掉 |
| 不丢条件和范围 | 安全条件、例外、数字、「仅限……」这类限定一个都不能丢。保不住就留长句，交付时说明 |
| 空话改完还是空话 | 原文没说出东西，就直接告诉读者「这段没有实际内容」，不要把它润色得很好读 |
